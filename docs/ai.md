# בינה מלאכותית: Claude וג'מיני

כל קריאה לבינה מלאכותית באפליקציה עוברת דרך דלת אחת: `data/ai/AiClient.kt`.
המסכים והלוגיקה לא יודעים איזה ספק עונה. הם מבקשים רק "רמה":
- `MAIN`: תמונות ארוחה, תשובות JSON, הערות למאמן, הצעות ארוחה.
- `LITE`: שורות קצרות של שמביולוק, ניסוח קצר של המאמן ("למה", סיכום אימון), פרק הסיפור.

## הספקים והמודלים

| ספק | קובץ | MAIN | LITE |
|---|---|---|---|
| Claude (אנתרופיק) | `ClaudeClient.kt`, `ClaudeConfig.kt` | `claude-sonnet-5-5` | `claude-haiku-5-5` |
| ג'מיני (גוגל) | `GeminiClient.kt`, `GeminiConfig.kt` | `gemini-3.6-flash` | `gemini-3.5-flash-lite` |

Claude: קריאת POST ל־`https://api.anthropic.com/v1/messages` עם הכותרות `x-api-key`, `anthropic-version: 2023-06-01`, `content-type`.
תמונה נשלחת כבלוק `image` עם `source` מסוג `base64`. התשובה נאספת מבלוקי `text` במערך `content`.
אין מצב JSON מיוחד: ההנחיה דורשת JSON בלבד, ו־`AiClient.parseJsonLoose` מסיר גדרות ``` וטקסט מסביב.
אם המודל דוחה את `temperature` (שגיאה 400), נשלחת אותה בקשה שוב בלי הפרמטר.
אם התשובה ריקה כי נגמר תקציב הטוקנים (`stop_reason = max_tokens`), יש ניסיון אחד נוסף עם תקציב גדול יותר.

## איזה ספק עונה, ומה קורה כשהוא נופל

ההגדרה נשמרת ב־`Prefs.aiProvider` ומגובה בענן:
- `auto` (ברירת המחדל): Claude אם יש לו מפתח, אחרת ג'מיני.
- `claude`: קודם Claude, ואז ג'מיני.
- `gemini`: קודם ג'מיני, ואז Claude.

כל ספק נשאל קודם דרך השרת (`AiProxy`, ראו למטה), ורק אם השרת לא זמין (עוד לא הותקן, לא עונה) ישירות עם מפתח שאפוי בגרסה.
הסדר המלא: שרת ← מפתח מקומי ← הספק השני (שוב שרת ← מפתח מקומי).
אם השרת הגיע לספק והספק נכשל (מכסה, עומס), לא מנסים את אותו ספק ישירות, כי זה ייכשל באותה צורה. עוברים לספק השני.
כשהספק הראשון לא עונה (אין רשת, מכסה, שגיאה, JSON לא תקין), `AiClient` מנסה את השני.
אם אף אחד לא עונה, הקורא מקבל null וממשיך עם הטקסט הרגיל שבלי בינה מלאכותית. שום דבר באפליקציה לא תלוי בתשובה.

`AiClient.enabled` אומר אם תכונות הבינה המלאכותית קיימות: תמיד כן כשהשרת פעיל (`AiProxy.ON`), או כשיש מפתח מקומי.

## המפתחות

המפתחות לא כתובים בקוד ולא במסמכים.

בשרת (המצב הרגיל, גם לחברים): הסודות `ANTHROPIC_API_KEY` ו־`GEMINI_API_KEY` שמורים ב־Supabase, והפונקציה `ai` משתמשת בהם.
הטלפון לא מחזיק שום מפתח.

בגרסה עצמה (זמני, רק לגרסאות של תמיר): מסודות המאגר בגיטהאב, בזמן הבנייה:
- `ANTHROPIC_API_KEY` ← `BuildConfig.CLAUDE_KEY`
- `GEMINI_API_KEY` ← `BuildConfig.GEMINI_KEY`

הם נאפים רק כשמשתנה המאגר `BAKE_AI_KEYS` לא שווה `false` (ברירת המחדל: נאפים).
אחרי שהשרת עובד מעבירים אותו ל־`false`, ומאז אין מפתחות בקובץ ההתקנה.
גרסה עם מפתחות אפויים אף פעם לא מתפרסמת במאגר הציבורי (`.github/workflows/build.yml` מדלג על הפרסום הציבורי).

## השרת: הפונקציה `ai` ב־Supabase

הקוד: `supabase/functions/ai/index.ts` (Deno, TypeScript). הלקוח באפליקציה: `data/ai/AiProxy.kt`.

הבקשה: `POST https://oacijyezkwmysertkmvl.supabase.co/functions/v1/ai` עם הכותרות `apikey` ו־`Authorization: Bearer` (מפתח ה־anon),
וגם `x-profile-code` (קוד השחזור של המשתמש). הגוף:
`{provider: "claude"|"gemini", tier: "MAIN"|"LITE", system?, json?, temperature?, maxTokens?, parts: [{text} | {imageBase64, mime}]}`.
התשובה: `{text, provider, error?}`.

בדיקות בשרת: קוד בפורמט `XXXX-XXXX-XXXX`, כל תמונה עד 5 מגה, `maxTokens` עד 16000. אין מגבלת שימוש.

### מי רשאי להשתמש בבינה המלאכותית (נעילה לפי קוד שחזור)

כתובת השרת ומפתח ה־anon נמצאים בתוך האפליקציה, ולכן הם לא סוד: מי שמחזיק את קובץ ההתקנה או את הקוד יכול לקרוא אותם.
המנעול האמיתי הוא קוד השחזור האישי (הגדרות ← "החשבון שלי"), שנמצא רק בטלפון.

- משתמשים קיימים: קוד שכבר השתמש בבינה המלאכותית בהצלחה לפני 23.11.2026 (לפי הטבלה `ai_log`, שרק הפונקציה כותבת אליה) מורשה אוטומטית. כך הבעלים והחברים שכבר היו לא צריכים לעשות כלום.
- משתמש חדש: מוסיפים את קוד השחזור שלו לסוד `AI_ALLOWED_CODES` (Supabase ← Edge Functions ← Secrets), קודים מופרדים בפסיקים.
- בקשה עם קוד אחר נענית ב־403 ולא מגיעה לספק הבינה המלאכותית, כך שהיא לא עולה כסף.
- אחרי שינוי בקוד הפונקציה צריך לפרוס אותה מחדש. שינוי של הסוד בלבד לא דורש פריסה.
- קוד השחזור לא נכתב אף פעם בקוד, במסמכים או בהודעות שמירה. בדיקת השרת בגיטהאב קוראת אותו מהסוד `HAMASA_PROFILE_CODE`.

כללי הניסיון החוזר זהים ל־`ClaudeClient` ו־`GeminiClient` (בלי `temperature` אם נדחה, תקציב גדול יותר אם התשובה ריקה, חשיבה נמוכה בג'מיני).
כל קריאה נרשמת בטבלה `ai_log` (מי, איזה ספק, הצליח או לא, כמה זמן). הטבלה נוצרת ב־`docs/multiuser.sql`. אם אין טבלה, פשוט לא נרשם.

### התקנה (פעם אחת, דרך לוח הבקרה של Supabase)

1. Edge Functions ← Secrets: מוסיפים `ANTHROPIC_API_KEY` ו־`GEMINI_API_KEY` (אותם מפתחות כמו בסודות של גיטהאב).
   `SUPABASE_URL` ו־`SUPABASE_SERVICE_ROLE_KEY` כבר קיימים שם לבד.
2. Edge Functions ← Deploy a new function ← Via Editor. השם חייב להיות בדיוק `ai`.
   מדביקים את כל התוכן של `supabase/functions/ai/index.ts` ולוחצים Deploy.
3. "Verify JWT": משאירים דלוק. האפליקציה שולחת את מפתח ה־anon כ־`Authorization: Bearer`, והוא JWT תקין.
   (אפשר גם לכבות, כי ממילא נדרש קוד שחזור. דלוק עדיף.)
4. בדיקה מהמחשב (מחליפים את `ANON` במפתח ה־anon מ־`data/cloud/CloudConfig.kt` ואת הקוד בקוד מההגדרות):

```
curl -s https://oacijyezkwmysertkmvl.supabase.co/functions/v1/ai \
  -H "apikey: ANON" -H "Authorization: Bearer ANON" \
  -H "x-profile-code: ABCD-EFGH-JK23" -H "content-type: application/json" \
  -d '{"provider":"claude","tier":"LITE","parts":[{"text":"ענה במילה אחת בעברית: שלום"}]}'
```

   מצופה: `{"text":"שלום","provider":"claude"}`. אותו דבר עם `"provider":"gemini"`.
5. באפליקציה: הגדרות ← בינה מלאכותית ← "בדיקת חיבור". מצופה: "ענה (דרך השרת)".
6. רק אחרי שזה עובד: בגיטהאב, Settings ← Secrets and variables ← Actions ← Variables, יוצרים `BAKE_AI_KEYS` = `false`.
   מהבנייה הבאה אין מפתחות בקובץ, והגרסה מתפרסמת גם במאגר הציבורי.

כל עוד הפונקציה לא מותקנת, השרת עונה 404, האפליקציה מדלגת עליו לעשר דקות ומשתמשת במפתח המקומי (אם יש).
בכרטיס בהגדרות זה מופיע כ"השרת עוד לא הותקן".
